`scripts/tar-changed.sh` creates a `.tar.gz` archive containing only the files Git reports as changed in the repo.

It works like this:

1. It `cd`s to the Git repo root, so paths are always relative to the repo.
2. It runs `git status --porcelain -z --untracked-files=all` and reads each entry. `-z` makes it safe for unusual filenames. `--untracked-files=all` lists individual files inside new folders, not just the folder.
3. It keeps modified, added, renamed, and untracked files. It skips deleted files, since they no longer exist on disk.
4. It writes the archive to the path you pass as the first argument, or to `changed-YYYYMMDD-HHMMSS.tar.gz` in the repo root by default. It then prints the list of files it packed.
5. If there are no changes, it prints `No changed files.` and exits without creating an archive.

It also sets `COPYFILE_DISABLE=1` and tries `tar --no-xattrs` so macOS does not add `._*` AppleDouble files that clutter Linux extractions. If that tar call fails, it retries with plain `tar`.

Git-ignored files such as `.env`, `node_modules/`, and most of `data/` are not included, because Git does not report them.

Usage:

```bash
scripts/tar-changed.sh                 # writes changed-<timestamp>.tar.gz in the repo root
scripts/tar-changed.sh my-changes.tgz  # writes to the given path
```
